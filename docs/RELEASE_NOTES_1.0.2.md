# NTM 1.0.2 — 补齐论文的「局部 AI」

> **发布于 2026-11-15**
> 下载：`NTM1.0.2.zip`（1.37 MB）· UE 5.8 Win64

## 一句话

1.0.1 只实现了 LLF-LUT 论文的**全局**一半。1.0.2 把**局部**那一半也接进了管线：边缘条件输入、48 个学习出来的局部参数、Durand 分解重写局部算子。

---

## 为什么做这个版本

1.0.1 的局部算子是这样的：

```hlsl
log2(gain) = 0.60*(G1-G3) + 0.25*(G0-G1) + 0.10*(G1-G2)
out = LUT(scene * gain)      // 乘在曲线【之前】
```

三个系数是**手调的常数**，换场景类型不会自适应。而论文的核心贡献之一，正是**用轻量网络学习局部拉普拉斯滤波器的参数图**。

所以这一版把它补上。

---

## 改了什么

### 1. 输入加边缘通道（论文的 Canny 条件）

论文明确说局部滤波器的参数图要 **conditioned on a Canny edge map** —— 网络必须知道边缘在哪，才知道局部滤波器能推到多强而不出光晕。

输入契约 **48 → 49 通道**：

| 通道 | 内容 |
|---|---|
| 0–2 | PQ 编码 RGB（128×72） |
| **3** | **边缘强度（新）**：1/2 分辨率 log2 亮度的 Sobel 幅值 / 3 |
| 4–5 | log2 均值 / log2 p99.99 |
| 6–16 | 显示与场景标量（13 个） |
| 17–32 | 4×4 分块 log2 亮度 |
| 33–48 | 16 档 log2 亮度直方图 |

引擎侧在 assemble pass 里用 8 次采样现算 Sobel，训练侧用同一定义（`ntmo_local.edge_channel()`），两边一致。

### 2. 输出扩展 8 → 56 维

```
out[0..7]   全局色调曲线 8 个控制点（原有）
out[8..55]  4×4 网格 × 3 通道的局部强度（新）
```

参数量 **323,767**（论文 292K，同量级）。

打包用 **MatMul × 0/1 放置矩阵**，不用 Concat —— 因为 `NNERuntimeRDGHlsl` 不支持 Concat，而 `Pad` 会被降级成 Concat。

### 3. 局部算子按 Durand 分解重写

**旧版**（手调系数，乘在曲线前）：

```hlsl
log2(gain) = 0.60*(G1-G3) + 0.25*(G0-G1) + 0.10*(G1-G2)
out = LUT(scene * gain)      // 曲线会把刚提的细节立刻压回去
```

**新版**（学习系数，加在曲线后）：

```hlsl
corr = s_base*(curve(base) - curve(logY))    // 基频非线性压缩
     + s_mid *(G1 - G3)                      // 粗频带
     + s_high*(G0 - G1)                      // 细频带
out = LUT(scene) * exp2(corr)                // 显示域乘性补偿
```

三个关键改动：

1. **加在曲线之后** —— 旧版加在曲线前，曲线肩部会立刻把细节重新压缩掉。这正是"提了细节但高光还是平的"的根因。
2. **LUT 改为存线性显示值** —— 转移函数（sRGB/PQ/Rec709）移到像素着色器、在补偿之后。乘在 PQ 编码值上是错的（PQ 对亮度非线性）。
3. **引导上采样被删掉** —— 校正场由 4×4 学习参数 × 平滑频带差构成，本身平滑，双线性足够。旧的 8-tap 双边上采样移除，**更省**。

### 4. 标签怎么来的

`ntmo_local.py`：对每张 HDR 图，以 **Durand 参考**为目标

```
ref_log = curve(base) + detail
target  = ref_log - curve(logY)
```

在每个 4×4 tile 上解 3×3 最小二乘，拟合 `s_base / s_mid / s_high`。三个回归量刻意不相干：`(G0-G1)` 与 `(G1-G3)` 是互不重叠的频带，`(c3-c0)` 是曲线的非线性段。若把中间项写成 `(G0-G3)` 就会与另外两项完全共线、矩阵奇异。

## ⚠️ 一个诚实的负面结果

**学出来的局部算子，当前对画面的实际贡献接近零。**

同机位、只切 `r.NTMO.Local 0/1`：

| | 高频能量 | 全局 std |
|---|---|---|
| 局部 AI 开 | 0.02577 | 0.1784 |
| 局部 AI 关 | 0.02642 | 0.1790 |

开着反而略降 2.5% 高频能量。

**原因不是玄学**：标签目标是"完整保留细节"（Durand detail=1），而公式里的 `(c3-c0)` 与 `(G0-G3)` 两项**在数学上就能精确表达该目标**（系数 ≈1）。最小二乘给出一组几乎恒等的解，网络学到的是近似常数 —— 没有"内容自适应"的自由度可学。

真正该学的是**分区域的细节取舍**（噪声区少留、纹理区多留），而现标签没有编码这个信息。

1.0.3 会继续处理这个问题。

## 顺带修掉的三个健壮性问题

| 问题 | 影响 | 修复 |
|---|---|---|
| 曲线输出可能超过面板峰值 | 误预测时整幅过曝 | LUT bake 里对控制点做物理钳制 `clamp(knot, log2(minNits), log2(peakNits))` |
| Saved 配置被写入 UTF-8 BOM | UE 的 ini 解析整段失效，设置不生效 | 一律无 BOM 写入 |
| 崩溃后自动保存残留 | 启动弹出「恢复包」对话框并**阻塞**编辑器 | 清理 `Saved/Autosaves` |

## 升级注意

- 输入契约从 48 → 49 通道、输出 8 → 56，**旧模型不兼容**（会自动退回解析曲线，不会崩溃）
